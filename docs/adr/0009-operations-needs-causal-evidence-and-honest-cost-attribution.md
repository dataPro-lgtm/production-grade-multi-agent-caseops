# ADR-0009：运行结论必须来自跨层因果证据与诚实成本归因

- 状态：Accepted
- 日期：2026-07-27
- 决策者：CaseOps maintainers

## 背景

多 Agent 系统的顶层 HTTP 状态、系统步骤状态和用户 Goal 结果可能不同。A2A 依赖中断时，Supervisor 可以正确完成收敛步骤并返回结构化响应，但下游委托任务已经失败，最终 Goal 仍未成功。只看顶层日志或一个总成功率会把症状当成根因。

成本也存在类似问题。确定性执行模式有步骤、上下文、委托和安全决策等可核验资源记录，但没有模型 token、供应商账单或版本化价格表。此时给出货币成本会制造虚假精度。

## 决策

1. 运行评估是显式、幂等、租户隔离的持久化操作，只接受终态系统运行。
2. 因果诊断从 `system_runs` 下钻到 `system_steps`、`collaboration_runs` 和 `delegated_tasks`，按持久化时间与错误码确定首个失败点。
3. Incident Bundle 只保存稳定引用、摘要、数量、事实时间线和版本，不复制原始 Prompt、工具参数或业务载荷。
4. 资源归因分别记录步骤尝试、上下文运行、委托尝试和安全决策，不强行合并不同单位。
5. 只有存在真实用量、币种和版本化价格表时才计算货币成本；否则货币字段必须为 `null`，并明确 `pricing_status=not_configured`。
6. GameDay 必须同时留下健康基线、事故评估和恢复评估；仅恢复容器健康不构成恢复证明。

## 结果

优点：

- 顶层受控拒绝不会遮蔽下游首故障；
- 事故证据可以重放、审计和跨版本比较；
- 成本数据保持可解释，不用估算值冒充事实；
- 恢复判断与用户 Goal、安全边界和持久化证据绑定。

代价：

- 诊断服务必须理解多层状态所有权；
- 运行评估和成本事件增加存储与 Schema 演进责任；
- 新依赖和新故障模式需要补充新的因果适配器与 GameDay。

## 未选择的方案

### 让 LLM 阅读日志后自由总结

拒绝。它可以辅助归纳，但不能替代确定性租户边界、证据引用、幂等记账和首故障判定。

### 只观察顶层 HTTP 与系统步骤

拒绝。它无法区分“Supervisor 正确收敛失败结果”和“下游任务成功”。

### 用固定单价估算所有运行成本

拒绝。缺少真实 token、provider、model、region、币种和价格版本时，固定单价会产生不可审计的虚假精度。
