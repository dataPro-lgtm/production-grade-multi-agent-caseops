# ADR-0002：先建设 Agent 控制面，再提高模型自治

- 状态：Accepted
- 日期：2026-07-23
- 对应里程碑：Chapter 2 / Slice 1

## 背景

第 1 章的确定性流程能稳定判断结构化材料，但 C-102 同时存在尚未归一的来源材料。仅增加一个更长的 Prompt 可以让模型尝试处理这种差异，却不能回答以下工程问题：谁授权调用、参数由谁校验、失败如何重试、重复调用如何停止、进程崩溃后从哪里恢复、每一步如何审计。

## 决策

我们把模型定位为 planner，而不是执行主体，并在它与业务工具之间加入独立控制面：

1. 每轮 planner 只能返回一个工具提议或一个终态；
2. 工具提议必须通过 Pydantic/JSON Schema 契约；
3. 运行时根据可信 Principal 做 allowlist、scope、风险与资源边界授权；
4. 工具通过 MCP Streamable HTTP 执行，租户和任务从短期签名令牌获得；
5. 状态迁移、工具账本和检查点持久化；
6. step、重复动作指纹、timeout 和 retry 均有硬上限；
7. CI 使用非模型的 `ConformancePlanner` 验证控制面，真实模型走同一运行时。

Slice 1 只开放只读工具。任何写工具在加入前必须说明幂等键、效果确认、补偿或人工审批策略。

## 选择 MCP 的边界

MCP 用于标准化 host/client/server 之间的工具发现与调用，不承担业务授权本身。工具注解只是提示；服务端仍验证令牌、作用域、租户和资源。应用内部紧耦合、低延迟的确定性调用仍可保留本地端口，不为“协议统一”强行远程化。

## 被否决的方案

### 让模型直接生成 SQL

它把数据权限、Schema 演进和查询成本暴露给概率系统，无法形成稳定的最小权限面。

### 只依赖框架的内存消息历史

消息历史不是恢复契约，不能可靠表示工具是否已经执行、外部效果是否已经发生。

### 在测试中固定模型输出

这会把随机性和外部服务状态引入控制面回归，无法定位失败来自模型还是运行时。模型适配器应有独立契约测试和可选在线评测。

### 声称 Exactly Once

分布式调用存在“工具已成功、结果尚未持久化”的崩溃窗口。Slice 1 通过只读重放规避副作用；未来写操作采用业务幂等和效果账本，不做虚假的恰好一次承诺。

## 结果

收益是执行链可解释、可测试、可审计，并且更换模型不改变权限边界。代价是新增运行记录、检查点、工具账本、任务令牌与 MCP 服务，单次调查也会多出协议和持久化开销。这个代价是有意承担的，因为自治能力只有进入控制系统后才适合生产。
