# ADR-0005：把生产级定义为可执行的运行保证

- 状态：Accepted
- 日期：2026-07-27
- 决策者：CaseOps maintainers

## 背景

Slice 3 已经能够构建受治理的证据产品，但“代码能在本机启动”不能证明系统具备生产属性。请求跨越 API、A2A 和 MCP 后，任何一层的超时失控、错误健康检查、遥测断链或不可恢复的数据损坏，都可能把正确的业务逻辑变成不可运营的服务。

生产基础设施也不能只表现为一组 YAML。部署、遥测和备份配置必须由同一套自动化验收证明，否则文档中的 SLO、RTO 和降级策略没有工程约束力。

## 决策

CaseOps 将生产运行能力定义为四组可执行保证：

1. **有界执行**：入口把相对超时转换为绝对 deadline，并通过 W3C Trace Context 与下游传播；下游只能缩短预算，不能重新获得完整超时。
2. **有语义的健康检查**：liveness 只回答进程是否存活，startup 验证数据库迁移版本，readiness 区分关键依赖与可选依赖。数据库不可用返回 `503 unavailable`；A2A 或 MCP 不可用返回 `200 degraded`，保留仍可服务的 API 能力。
3. **可关联的运行证据**：API、A2A、MCP 使用 OpenTelemetry SDK，把同一 Trace 发送到 Collector 和 Tempo；Prometheus 只采集低基数 SLI，告警面向用户症状、错误预算和可执行处置。
4. **经过恢复验证的数据保护**：备份必须带格式、迁移版本、大小和 SHA-256 清单；恢复必须在隔离数据库执行，并比较内容签名、迁移版本和业务不变量。

本地平台基线使用 Docker Compose、OpenTelemetry Collector、Tempo、Prometheus 和 Grafana。它用于验证运行契约，不冒充企业最终的多副本拓扑或灾备架构。

## 后果

### 正向

- 每个请求都有统一 Trace 与单调递减的时间预算；
- Kubernetes 或其他编排器可以依据不同探针语义做正确决策；
- 依赖降级不会被误报为进程死亡，也不会无条件接收新流量；
- 告警、Trace 和恢复报告可以成为发布证据；
- 数据库“备份成功”被升级为“业务数据经过恢复验证”。

### 代价

- 服务启动和测试增加了遥测 SDK、Collector 与存储组件；
- 异步导出存在短暂可见性延迟，验收必须等待完整 Trace，而不是看到第一个 Span 就结束；
- readiness 的关键/可选依赖分类需要随业务能力变化持续维护；
- 本地恢复演练不能证明异地容灾 RPO，生产环境仍需 WAL 归档、PITR 和定期灾备演练。

## 被拒绝的方案

- **每个服务独立设置固定 timeout**：会在多跳调用中放大总耗时，并在上游取消后继续浪费资源。
- **一个 `/health` 同时承担存活与就绪**：会把下游波动转化为重启风暴，或让不具备服务条件的实例继续接流量。
- **直接从服务写入某个遥测后端**：增加后端耦合，失去 Collector 的批处理、限流和路由边界。
- **只验证 `pg_dump` 退出码**：无法发现错误的恢复命令、迁移不一致和业务不变量缺失。
