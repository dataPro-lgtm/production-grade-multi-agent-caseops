# ADR-0001：以确定性模块化单体作为 CaseOps 起点

- 状态：已接受
- 决策日期：2026-07-23
- 适用范围：CaseOps Slice 0

## 背景

C-102 的第一阶段目标是识别缺失材料并形成补件通知草稿。案件、规则版本和材料要求均可结构化表达，处理路径固定，外部动作风险明确。此时引入模型规划、多 Agent 委托或分布式状态，会增加测试空间和故障点，却没有已验证的业务收益。

## 决策

Slice 0 使用 Python 模块化单体，并把领域内核与运行时框架隔离：

- 领域对象表达案件、规则、证据与决策；
- 应用层编排确定性调查流程；
- SQLAlchemy 仓储端口隔离 PostgreSQL；
- 策略层禁止直接发送通知；
- FastAPI 提供版本化 HTTP 契约；
- 结果、审计与 Outbox 在同一事务内落库；
- 自动化测试与 CI 固定正确性基线。

## 后果

正面影响：

- 无需模型密钥即可运行完整 API；
- 业务规则和副作用边界可直接测试；
- 后续 Agent 方案可以与基线比较质量、延迟和成本；
- 领域层不依赖具体框架，便于替换适配器。

代价：

- 无法处理模糊自然语言、未知材料名称或动态取证路径；
- 当前只实现 API Key 鉴权，尚未接入企业身份提供方；
- Outbox 事件已原子落库，可靠发布 Worker 尚未实现；
- 尚未提供真实容量、可用性和恢复指标。

## 升级触发条件

只有出现以下可验证需求时才提高自治或拆分服务：

1. 处理路径必须根据中间证据动态改变；
2. 规则或材料无法仅靠结构化字段确定；
3. 某项能力需要独立权限、故障隔离或扩缩容；
4. 评测证明新架构的质量收益覆盖其延迟、成本和运维复杂度。
