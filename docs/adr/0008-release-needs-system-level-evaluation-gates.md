# ADR-0008：发布需要系统级评测门禁

- 状态：Accepted
- 日期：2026-07-27
- 决策者：CaseOps Architecture

## 背景

CaseOps 已经把上下文调查、多 Agent 协作、ToolGuard 与系统级收敛连成一条真实执行链。继续只用函数单测或最终文本相似度，会漏掉三类高风险回归：

1. 最终结论正确，但走错 Agent、证据或权限路径；
2. 单次运行正确，但重复运行出现语义漂移；
3. 局部指标改善，但跨租户隔离、证据绑定或幂等完整性退化。

评测对象因此必须是“模型、Agent、工具、Harness、数据与安全控制共同组成的系统”，而不是一段孤立回答。

## 决策

每个候选发布都运行版本化 Golden Dataset，并输出可机读的
`caseops.evaluation-report.v1`：

- Golden case 显式声明风险、执行模式、重复次数、请求与预期合同；
- 确定性 grader 分别检查契约、结果、路径、证据、安全与效率预算；
- 成功运行必须读取 Runtime Context Graph，并验证所有 Claim 都有
  `SUPPORTED_BY` 边；
- 每次成功运行都用另一租户身份反向读取该图，期望得到 404；
- 同一 case 的语义指纹在 N 次运行中必须一致；
- 候选结果与冻结的 v0.7.0 基线按 case、按层成对比较；
- 任一硬门禁下降即阻断发布，评测 JSON 作为 CI Artifact 留存。

LLM-as-Judge 不拥有硬门禁。将来只有在 rubric 版本化、盲测校准、与人工标注的一致性达到预设标准后，模型评分才可成为补充信号；它仍不能覆盖权限、证据、图不变量与副作用检查。

共享 CI 中不以 wall-clock latency 阻断发布。报告保留耗时诊断，但延迟 SLO 由目标环境遥测判定，避免把 runner 噪声误当产品回归。

## 后果

好处：

- 每个发布结论都有数据集版本、质量合同、基线和原始 trial 证据；
- “正确答案”与“正确过程”被同时检验；
- 幂等、租户隔离和零副作用从文档承诺变成发布门禁；
- 失败可定位到 case、repetition、layer 与 finding。

代价：

- Golden Dataset 必须像代码一样评审、版本化和防泄漏；
- 确定性基线不能代表真实模型分布，接入随机模型后仍需独立的统计评测；
- 目标环境的 SLO、成本和线上漂移需要第 9 章的 AgentOps 闭环承接。
